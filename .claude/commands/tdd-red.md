# /tdd-red

켄트 벡 TDD 사이클의 **Red** 단계. [CLAUDE.md](../../CLAUDE.md)의 TDD 원칙을 따른다.

## 절차

1. `TDD-IMPLEMENTS.md`를 읽는다.
2. 대상 항목을 정한다:
   - 인자(`$ARGUMENTS`)가 있으면 해당 항목 번호/테스트명을 찾는다.
   - 없으면 **위에서부터 `Red`가 체크되지 않은 첫 항목**을 고른다.
3. 그 항목의 `Red`가 이미 `[x]`면 진행하지 않는다 — 이미 Red 완료 상태이니 `/tdd-green`으로 진행하라고 사용자에게 알린다.
4. 선택한 항목의 "설명"을 기준으로, 가장 단순하고 의미 있는 이름의 실패하는 테스트 **하나**를 작성한다 (예: `should...`).
   - 이 단계에서는 **테스트만** 작성한다. 통과시키는 구현 코드는 작성하지 않는다.
   - 테스트 실패 메시지가 명확하고 유용하도록 작성한다.
5. `npm test`를 실행해 **실제로 실패하는지** 확인한다.
6. 실패를 확인했으면 `TDD-IMPLEMENTS.md`에서 해당 항목의 `Red` 체크박스를 `[x]`로 표시한다.
7. 결과를 보고한다: 무슨 테스트를 작성했는지, 실패 원인(정확한 에러 메시지), 다음 단계는 `/tdd-green`이라는 점.

## 하지 말 것

- 테스트를 통과시키는 프로덕션 코드 작성 금지.
- 여러 항목을 동시에 진행 금지 — 한 번에 정확히 하나.
- 이미 Green/Refactor까지 끝난 항목 재작성 금지.
