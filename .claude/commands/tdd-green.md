# /tdd-green

켄트 벡 TDD 사이클의 **Green** 단계. [CLAUDE.md](../../CLAUDE.md)의 TDD 원칙을 따른다.

## 절차

1. `TDD-IMPLEMENTS.md`를 읽는다.
2. 대상 항목을 정한다:
   - 인자가 있으면 해당 항목.
   - 없으면 **`Red`는 체크됐고 `Green`은 안 된 첫 항목**.
3. 대상이 없으면 (`Red` 미완료 항목뿐이면) 진행하지 않고, 먼저 `/tdd-red`를 실행하라고 안내한다.
4. 해당 테스트를 **통과시키는 데 필요한 최소한의 코드만** 구현한다. 그 이상은 금지 — 다른 항목 선구현, 불필요한 일반화, 아직 요구되지 않은 방어 코드 등을 넣지 않는다.
5. `npm test`를 실행해 대상 테스트가 통과하는지, 기존 테스트들이 깨지지 않았는지 확인한다.
6. 통과가 확인되면 `TDD-IMPLEMENTS.md`의 해당 항목 `Green` 체크박스를 `[x]`로 표시한다.
7. 커밋 규율(CLAUDE.md 참고): 모든 테스트 통과 + 논리적 단위 하나면 커밋 후보다. 행위적 변경 커밋 메시지(`behavioral: ...`)를 제안하되, **사용자 확인 없이 git commit을 실행하지 않는다.**
8. 다음 단계를 안내한다 — 정리할 하드코딩/구조 문제가 있으면 `/tdd-refactor`, 없으면 바로 다음 항목의 `/tdd-red`.

## 하지 말 것

- 테스트가 요구하지 않는 기능 추가 금지.
- 이 단계에서 리팩터링 금지 (`/tdd-refactor`에서 별도 진행).
- 사용자 확인 없이 git commit 실행 금지.
